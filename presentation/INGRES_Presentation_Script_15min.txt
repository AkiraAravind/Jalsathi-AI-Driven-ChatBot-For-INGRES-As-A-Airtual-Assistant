PHASE 1: PRESENTATION (7 MINUTES — 10 SLIDES)
================================================================================

----------------------------------------------------------------------
SLIDE 1: MOTIVATION OF THE THEME AND TITLE (45 seconds)
----------------------------------------------------------------------

"Good morning, respected panel members. We are Team TBP, and today we
present INGRES — India National Groundwater Resources Expert System.

India is facing one of its worst groundwater crises. Over 17 percent of
assessment units are classified as Over-Exploited, meaning water is being
extracted faster than nature can replenish it. States like Haryana, Delhi,
and Rajasthan have reached alarming depletion levels.

The Ministry of Jal Shakti generates massive groundwater reports through the
GEC framework every 2-3 years — but these reports are locked inside dense
Excel files and 200-page PDFs. No one can easily query them.

Our theme is Smart Water Management under e-Governance. The title INGRES
signifies a robust entry point — a gateway — into India's groundwater
knowledge. We aim to make this critical data accessible, interactive, and
intelligent using AI."

----------------------------------------------------------------------
SLIDE 2: PROBLEM STATEMENT (45 seconds)
----------------------------------------------------------------------

"Our problem statement is SIH25066, issued by the Central Ground Water Board
under the Ministry of Jal Shakti.

The core problems are fourfold:

First — Static Information Silos. The GEC-2015 methodology is a massive PDF
document. Officials must manually search through hundreds of pages to find
relevant formulas and data.

Second — High Cognitive Load. Groundwater estimation involves multiple
dependent variables. Misinterpreting one parameter can invalidate an entire
regional assessment.

Third — No Interactive Platform. There is no unified system where officials
can query data in natural language. Everything is done through spreadsheets
and email.

Fourth — Technical Accessibility. Non-domain experts like policymakers
cannot translate complex scientific terminology into actionable insights.

The ask is simple: Build an AI-powered chatbot that answers natural-language
questions about India's groundwater with accurate, data-grounded responses."

----------------------------------------------------------------------
SLIDE 3: ABSTRACT (40 seconds)
----------------------------------------------------------------------

"INGRES is a full-stack, AI-driven platform that transforms India's static
groundwater assessment data into a dynamic conversational interface.

We use a Retrieval-Augmented Generation architecture — or RAG — powered by
Google Gemini 2.0 Flash. Unlike generic LLMs that hallucinate numbers, our
system first retrieves actual data from a vector database, then generates
answers strictly grounded in that data.

The platform features a React frontend with modern UI, a FastAPI backend
with JWT-based OTP authentication, and a Supabase PostgreSQL database with
pgvector for semantic search.

It supports four retrieval paths: GEC Manual search for methodology queries,
semantic data search for district-level lookups, JEPA trajectory search for
trend prediction, and block-risk search for at-risk assessment units.

The system covers data across 36 states, 750+ districts, and 8000+
assessment blocks spanning multiple assessment years from 2017 to 2025."

----------------------------------------------------------------------
SLIDE 4: EXISTING SYSTEM AND PROPOSED SOLUTION (50 seconds)
----------------------------------------------------------------------

"In the existing system, government officials rely on manual PDF parsing of
GEC reports, spreadsheet-based computations prone to formula errors, and
there is no role-based access control. Data is shared via email and physical
files. Generic LLMs like ChatGPT will hallucinate groundwater numbers
because they lack domain-specific grounding.

Our proposed solution addresses every gap:

Instead of manual search — we provide natural language querying powered by
semantic vector search. Instead of spreadsheets — our system returns
structured, citation-backed answers with source references. Instead of
generic LLMs — we use RAG to ensure every answer is grounded in real CGWB
data. Instead of no access control — we implement JWT authentication with
OTP verification, role-based access for citizens and government officials,
and a dedicated Government Portal dashboard.

The key innovation is our hybrid retrieval architecture: we combine
traditional semantic search with a novel JEPA-based trajectory encoder
that can predict which districts are trending toward over-exploitation —
something no existing system offers."

----------------------------------------------------------------------
SLIDE 5: SYSTEM ARCHITECTURE (50 seconds)
----------------------------------------------------------------------

"Our architecture follows a decoupled, three-tier design:

The Client Tier is a React Single Page Application built with Vite and
TypeScript. It features a modern chat interface, a landing page with
animations, and a Government Official dashboard.

The Application Tier is powered by FastAPI with Uvicorn as the ASGI server.
It handles authentication endpoints, chat processing, file upload,
PDF export, and chat history management.

The AI and Data Tier is where the intelligence lives. Our RAG Engine has
four retrieval paths: First, the query is classified — is it about
methodology, data lookup, trend prediction, or block risk? Then the
appropriate retrieval path is activated. We embed the query using
a 1024-dimensional sentence transformer, search Supabase pgvector using
cosine similarity, and assemble context. Finally, Gemini 2.0 Flash
generates a grounded answer via OpenRouter with model fallback to LLaMA.

The database layer uses Supabase PostgreSQL with pgvector extension,
featuring tables for groundwater time-series data, GEC manual chunks,
block risk annexures, user accounts, and chat history — all secured
with Row Level Security."

----------------------------------------------------------------------
SLIDE 6: TECHNOLOGY STACK AND DATASET (50 seconds)
----------------------------------------------------------------------

"Our technology stack:

Frontend: React 18, TypeScript, Vite, Tailwind CSS, shadcn/ui components,
and Framer Motion for animations.

Backend: Python with FastAPI, Uvicorn ASGI server, Pydantic for validation,
and python-jose for JWT authentication.

AI/ML Layer: Sentence Transformers for embeddings, Google Gemini 2.0 Flash
as the primary LLM via OpenRouter API, with LLaMA 3 as fallback. We built
a custom RAG pipeline — no LangChain dependency.

Database: Supabase PostgreSQL 15 with pgvector extension for vector storage
and IVFFlat indexing for fast approximate nearest neighbor search.

Infrastructure: Docker Compose for containerization, Nginx as reverse proxy.

Our datasets come directly from the Ministry of Jal Shakti's GEC Assessment
Reports. We process 8 dataset types: Annexure 1 through 4 covering state,
district, and block level data; Attribute Tables with 8092 rows and 26
columns per assessment year; Central reports with 153 columns; and State
reports for all 36 states. In total, we handle over 40,000 data records
across 5 assessment years."

----------------------------------------------------------------------
SLIDE 7: RESULTS AND SCREENSHOTS (45 seconds)
----------------------------------------------------------------------

"Let me walk you through our key results:

Accuracy: Our RAG mechanism achieves over 95 percent factual accuracy for
queries within GEC-2015 scope. Hallucination drops to near-zero due to
strict context-only prompting.

Performance: Average API response time is 1.2 to 1.8 seconds including
semantic search and LLM generation. Streaming mode delivers tokens
in real-time for better user experience.

The UI features a premium dark-mode chat interface with markdown rendering,
citation display, and interactive Chart.js visualizations for trend data.
The Government Portal dashboard shows real-time analytics — extraction
averages, at-risk block counts, monitored states, and critical versus
healthy state comparisons.

We support multilingual queries in English, Hindi, and Telugu with
automatic language detection and response translation. File upload
allows users to provide additional PDF or text context for queries."

----------------------------------------------------------------------
SLIDE 8: CONCLUSION (30 seconds)
----------------------------------------------------------------------

"In conclusion, INGRES represents a paradigm shift in how government
groundwater data is accessed and interpreted.

We have successfully transformed static GEC methodology and assessment
data into an intelligent, conversational platform. The RAG architecture
ensures factual accuracy. The hybrid retrieval system with JEPA trajectory
analysis enables predictive insights. And the secure, role-based platform
is production-ready for government deployment.

INGRES democratizes hydrogeological data — empowering researchers,
policymakers, and citizens to make accurate, data-backed groundwater
assessments through simple natural language queries."

----------------------------------------------------------------------

PHASE 3: QUESTION AND ANSWER (2 MINUTES)
================================================================================

"We are now happy to take your questions."

ANTICIPATED QUESTIONS AND PREPARED ANSWERS:

Q1: "How do you prevent hallucination in the LLM responses?"
A1: "We use strict RAG prompting. The LLM receives a system instruction
that says 'Answer ONLY from the provided context. Do NOT make up numbers.'
The context itself is real data retrieved from our vector database. If no
relevant data is found, the system explicitly states that the information
is not available rather than guessing."

Q2: "What embedding model do you use and why?"
A2: "We use a 1024-dimensional sentence transformer model. It provides
excellent semantic understanding for domain-specific text while being
efficient enough for real-time query processing. The embeddings are
stored in Supabase pgvector with IVFFlat indexing for fast similarity
search."

Q3: "How scalable is this system?"
A3: "Very scalable. Our architecture is containerized with Docker Compose.
The FastAPI backend is async and handles concurrent requests efficiently.
Supabase PostgreSQL can scale vertically and horizontally. We can deploy
on cloud platforms like AWS or Railway with minimal configuration changes."

Q4: "What is the JEPA trajectory encoder?"
A4: "JEPA stands for Joint Embedding Predictive Architecture. We adapted
this concept to encode temporal patterns in groundwater data. Each
district's extraction history across assessment years is encoded as
a trajectory vector. We can then search for districts whose trajectories
match a 'worsening' or 'improving' prototype — enabling predictive
trend analysis."

Q5: "How is authentication handled?"
A5: "We use OTP-based email authentication. Users register with their
email, receive a one-time password, and verify it. Upon verification,
a JWT token is issued with a 30-minute expiry. The token includes the
user's role — citizen or official — enabling role-based access control.
All passwords are hashed with bcrypt and never stored in plaintext."

Q6: "What datasets are you using?"
A6: "All datasets come from the official GEC Assessment Reports published
by the Ministry of Jal Shakti. We process 8 dataset types covering
Annexures 1 through 4, Attribute Tables, Central Reports, and State
Reports across 5 assessment years. The total data spans 36 states,
750+ districts, and 8000+ assessment blocks."
